# 01 — Upstream analysis: `kbdevs/omibutfree`

Analysed at commit `98b912f` ("failed swift transformation", 2026-02-17).
Local clone: `/Users/daphne/workspace/omibutfree`.

## 1. What it is

A Flutter (Dart `^3.9.2`) application, ~9,300 lines of Dart, that replaces the official
Omi app with a local-first client:

- connects to an Omi device over BLE and streams Opus audio,
- transcribes it (Deepgram cloud, or on-device via sherpa-onnx streaming Zipformer / Whisper),
- groups transcript segments into "conversations" using a 2-minute silence timeout,
- summarises each conversation with OpenAI and extracts *memories* and *tasks*,
- stores everything in SQLite, schedules local notifications for tasks,
- supports "hold-to-ask" (press the Omi button, speak a question, get the answer as a notification),
- has a partially working SD-card sync for offline recordings stored on the device.

The README badge says "Platform: iOS", but **this is a packaging accident, not an
architectural fact**: `.metadata` shows the project was generated with an `android`
platform folder, which the author later deleted. Every dependency in `pubspec.lock`
resolves an Android implementation (`flutter_blue_plus_android`, `record_android`,
`sherpa_onnx_android`, `opus_flutter_android`, `sqflite_android`,
`permission_handler_android`, `awesome_notifications`, `audioplayers_android`,
`path_provider_android`, `shared_preferences_android`, `share_plus`). There is
**no** `Platform.isIOS` branch and **no** custom platform channel in the Dart code.

## 3. Runtime architecture (as-is)

```
             ┌──────────────┐        ┌──────────────┐
 Omi device ─┤ BleService   │        │ MicService   ├─ phone mic (PCM16 16 kHz)
  (Opus)     └──────┬───────┘        └──────┬───────┘
                    │ Uint8List (3-byte hdr + opus)   │ Uint8List (pcm16)
                    ▼                                 ▼
             ┌─────────────────────────────────────────────────────┐
             │ AppProvider (ChangeNotifier, 1,395 lines)           │
             │  • strips header, OpusDecoderService → PCM16        │
             │  • routes bytes to the active transcriber           │
             │  • silence timer (2 min) → _saveCurrentConversation │
             │  • button state machine (hold-to-ask)               │
             │  • battery polling + notifications                  │
             │  • auto-reconnect timer (5 s)                       │
             └───┬───────────────┬───────────────┬─────────────────┘
                 │               │               │
        ┌────────▼───┐   ┌───────▼───────┐  ┌────▼──────────┐
        │ Deepgram   │   │ SherpaService │  │ WhisperService│  → List<TranscriptSegment>
        │ (WS, opus/ │   │ (streaming    │  │ (offline,     │
        │  linear16) │   │  zipformer)   │  │  3 s batches) │
        └────────────┘   └───────────────┘  └───────────────┘
                 │
        ┌────────▼───────────┐     ┌──────────────────┐     ┌────────────────────┐
        │ OpenAIService      │ ──▶ │ DatabaseService  │ ──▶ │ NotificationService│
        │ summarize / chat   │     │ sqflite v3       │     │ awesome_notif.     │
        └────────────────────┘     └──────────────────┘     └────────────────────┘
```

State management is `provider` with a single `AppProvider`; pages read it via
`Consumer<AppProvider>`. Navigation is a 5-tab `IndexedStack` (Live, History,
Memories, Tasks, Settings) plus pushed pages (conversation detail, chat, stats,
device settings, SD-card sync).

## 5. Defects and incomplete features found during review

Ordered by how much they matter for an Android port.

1. **BLE MTU is never negotiated.** iOS negotiates a large MTU automatically; Android
   defaults to 23 bytes. Omi audio packets are 83 bytes and SD-card packets are up to
   440 bytes. Without `requestMtu(512)` after connect, notifications will be truncated
   and nothing downstream will work. (The official Omi app requests MTU 512 on Android;
   confirmed in upstream `OmiBleForegroundService.kt` and the React Native SDK.)
2. **No background execution strategy for Android.** iOS relies on
   `UIBackgroundModes`. Android needs a foreground service with
   `connectedDevice` / `microphone` types, otherwise the process is frozen or killed
   within minutes of leaving the foreground.
3. **SD-card post-processing is stubbed.** `_transcribeWithWhisper`,
   `_transcribeWithSherpa`, and `_transcribeWithDeepgram` in `app_provider.dart`
   return placeholder strings; the synced `.bin` file is never actually transcribed.
   The transfer itself works ("sd card sync kinda works" in git history).
4. **Local STT produces no timestamps.** Sherpa/Whisper segments are emitted with
   `startTime = endTime = 0`, so `Conversation.duration` is 0 and the History UI shows
   nothing useful for local modes. The "with diarization" log line for Sherpa is false.
5. **Whisper mode has no VAD.** Audio is chopped every 3 seconds regardless of speech,
   cutting words. sherpa-onnx ships a Silero VAD that fixes this cheaply.
6. **`AppProvider` is a god object.** BLE lifecycle, audio routing, transcriber
   selection, LLM post-processing, persistence, notifications, and the button state
   machine all live in one class; the summarise→memories→tasks pipeline is duplicated
   (live path and SD-card path). Untestable as-is.
7. **`BleService` re-runs `discoverServices()` on every read/write** (battery, gain,
   dim, haptic, storage). Slow on Android and racy with the audio stream. Characteristics
   should be cached once after connect.
8. **Subscriptions leak across reconnects.** The button `onValueReceived` listener is
   never cancelled; `BleService` is a singleton whose `dispose()` closes broadcast
   controllers, after which the app cannot recover without restart.
9. **Notification IDs use `task.id.hashCode`.** Dart does not guarantee `String.hashCode`
   stability across VM versions; cancelling a reminder after an app update may miss.
10. **`resource://raw/res_custom_notification`** is referenced for the task channel but
    no such resource exists (it would have to live under `android/app/src/main/res/raw/`).
11. **API keys in plaintext SharedPreferences.** Acceptable on iOS (keychain-backed
    NSUserDefaults is not, but the sandbox helps); on Android use
    `flutter_secure_storage` (EncryptedSharedPreferences).
12. **Hardcoded Deepgram `nova-2`** and a stale OpenAI pricing table. Make model and
    price table configurable.
13. **iCloud backup** is a settings toggle backed only by an entitlement; there is no
    sync code. Drop for Android; keep JSON export/import.
14. **Memory/task dedup** is an O(n) substring scan over the whole table. Fine for a
    personal device, but move it to SQL `LIKE` or an index before it becomes a problem.
15. **Deepgram usage accounting** sums the `duration` field of every result message,
    including interim results, which over-counts minutes. Use only `is_final` messages
    or the `Metadata` message on close.
16. **No tests.** Only the Flutter template widget test.

## 6. What is genuinely reusable

- All five *service* classes for STT/LLM/decoding (`deepgram`, `sherpa`, `whisper`,
  `openai`, `opus_decoder`) can be copied nearly verbatim behind interfaces.
- `database_service.dart` and `models/` are portable as-is (schema v3 is a fine v1).
- `ble_service.dart` contains the correct UUIDs and packet parsing; it needs MTU,
  caching, and lifecycle fixes rather than a rewrite.
- `sdcard_sync_service.dart` contains a working transfer loop; only the post-processing
  needs implementing.
- The UI (`pages/`) is portable and can be shipped unchanged for the first Android
  build, then iterated.

## 7. Conclusion

The Dart layer is platform-neutral. An "Android version" is therefore:

1. regenerate the Android platform shell and declare permissions,
2. add the two Android-only behaviours the app lacks (MTU negotiation, foreground
   service),
3. fix the lifecycle defects that iOS tolerated,
4. finish the stubs (SD-card transcription, local STT timestamps),
5. refactor `AppProvider` so the above can be tested without a physical device.

See `02-tech-stack-decision.md` for why this beats a native rewrite.
